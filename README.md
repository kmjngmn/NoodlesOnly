# 영써티

약 10명이 함께 쓰는 한 스터디용 모바일 웹앱입니다. 공개 열람, 개인 사진 인증, 운영자 검토와 주간 정산을 지원합니다.

## 실행

Python 3.12 이상, 영구 저장 가능한 디스크를 사용합니다.

```bash
cd /workspace/NoodlesOnly
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python app.py init-admin
.venv/bin/gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 --timeout 60 'app:create_app()'
```

`init-admin`은 비밀번호를 터미널에서 두 번 입력받고 해시만 저장합니다. 처음 설정하거나 재설정할 때 사용합니다. 10자 이상을 사용하세요. 기본 비밀번호는 없습니다. 먼저 별명으로 회원 가입한 후 화면 아래 **운영자 입장**에서 이 비밀번호를 입력하면 자신의 계정으로 인증하면서 운영할 수 있습니다.

브라우저에서 서버의 8000번 포트로 접속합니다. 같은 서버에 접속하는 모든 기기는 동일한 데이터베이스와 사진을 공유합니다. 실제 참여자는 최초 가입 시 표시되는 4자리 코드를 보관하세요. 로그인은 최대 90일 유지되며 운영자 권한은 12시간마다 다시 확인합니다. 운영자는 별명별 식별코드 목록을 열 수 있습니다.

## 동작과 정산 규칙

- 한국 시간 자정 마감, 월요일~일요일 기준입니다. 제출 시작 시각을 서버에서 기록하므로 사진 처리가 자정을 넘겨 끝나도 제출한 날로 인정합니다.
- 회원당 하루 한 장. JPG/PNG/WebP, 요청 크기 최대 10MB. 당일 사진 교체는 가능하며 이전 파일은 삭제됩니다. 회원은 과거 날짜로 제출할 수 없습니다. 사진을 올리거나 교체하면 즉시 인증 완료로 반영합니다.
- 사진은 브라우저에서 최대 1800px JPEG(2MB 이하, 최대 2,000,000바이트)로 압축하고 서버에서 EXIF를 제거합니다. 업로드 시점부터 **21일(3주)** 뒤 사진 열람을 차단하고, 일반 서버에서는 매시간과 시작 시, Vercel에서는 매일 예약 작업으로 만료 파일을 정리합니다. 기존 사진에도 같은 보관 기간을 적용하며 인증/정산 기록은 남습니다. Vercel 삭제 작업은 매일 한국 시간 오전 3시에 실행되어 실제 파일 삭제는 만료 후 다음 실행 시 완료됩니다. 수동 정리는 `python app.py cleanup`입니다.
- 정산 목표는 `해당 주 참여일 수 - 1일`. 첫 주는 가입일부터 계산합니다. 6~7일 승인 0원, 5일 승인 1,000원, 4일 승인 2,000원입니다. 하루짜리 첫 주는 목표 0일입니다.
- 미인증일 중 하루를 자동 휴식으로 표시합니다. 운영자가 특정 하루를 지정하거나 자동 지정으로 돌릴 수 있습니다. 인증된 날을 휴식일로 중복 지정할 수 없습니다.
- 진행 중인 주의 벌금은 확정되지 않습니다. 주가 끝나면 인증 완료 횟수를 기준으로 벌금을 확정합니다.
- 운영자는 사진을 사후 점검하거나 무작위로 확인해 문제가 있는 인증을 반려하고, 잘못 반려한 기록은 다시 승인할 수 있습니다. 과거 인증 수정, 휴식 지정/해제, 확정 벌금 납부 체크도 가능합니다. 인증 기록을 다시 검토하거나 수정하면 그 주의 납부 체크를 초기화하므로 다시 확인하세요. `미인증으로 변경`은 해당 기록과 사진을 삭제합니다.
- 계정 없이 전체 현황, 정산, 사진을 열람할 수 있습니다. 정산 공유 버튼은 해당 주를 여는 링크를 만듭니다. 개인 코드와 운영자 기능은 공개 API에 포함하지 않습니다.

## 사진 인증 방식

유효한 사진 파일을 업로드하면 즉시 인증 완료로 처리합니다. 사진 내용은 자동 판독하지 않으며, 운영자가 **운영 → 회원별 날짜**를 눌러 사진을 점검하고 문제가 있으면 반려합니다. 반려하면 해당 날짜는 인증 횟수에서 제외되고 벌금이 다시 계산됩니다. 해당 주의 납부 체크도 초기화됩니다.

기존 확인 대기 기록은 인증 완료로 전환하며, 운영자가 이미 반려한 기록은 유지합니다.

## 공개 배포와 데이터 보관

선택한 배포 방식은 **Vercel + Supabase**입니다. 연결·환경변수·사진 정리 설정은 [VERCEL.md](VERCEL.md)에 있습니다. Vercel에서는 Supabase에 영구 저장하고, 아래 영구 디스크 안내는 로컬 개발 및 일반 서버에 해당합니다.


공개 사이트는 https://engthirty.vercel.app 입니다. 일반 서버에서 함께 쓰려면 Python 호스팅, HTTPS 주소와 **영구 저장 디스크**가 필요합니다. 데이터가 매번 지워지는 무료 임시 디스크에는 배포하지 마세요. 무료 제공량과 영구 저장 지원은 호스팅 제공자에 따라 다르므로 무료 운영을 보장하지 않습니다.

- `DATA_DIR`: 데이터 저장 디렉터리. 기본은 저장소의 `data/`. SQLite, 압축 사진, 세션 키, 운영자 비밀번호 해시를 보관합니다. 배포 시 영구 디스크 경로로 설정합니다.
- `COOKIE_SECURE=1`: HTTPS 공개 배포 시 반드시 설정합니다. 로컬 HTTP 개발에서는 설정하지 않습니다.
- `ADMIN_PASSWORD`: 선택 사항. 호스팅의 비밀 환경변수로 관리할 수도 있습니다. 설정하면 `init-admin`으로 저장한 비밀번호보다 우선합니다. 환경변수를 바꾸면 재시작합니다.

영구 디스크를 유지한 채 배포해야 재시작 후 기록과 계정이 남습니다. 하나의 Gunicorn worker와 여러 스레드를 기본으로 합니다. HTTPS 리버스 프록시를 사용하고, 앱의 8000번 포트는 내부에 둡니다. 프록시 환경에서 로그인 요청 제한은 프록시 주소 기준으로 합산될 수 있습니다. 원본 IP 헤더는 임의로 신뢰하지 않습니다.

사진은 공개 열람 대상이므로 캡처에 개인정보가 포함되지 않게 안내하세요. 브라우저가 저장한 사진이나 외부 공유 사본까지 회수되지는 않습니다. 정기 백업은 데이터 디렉터리 전체를 서버 정지 상태에서 보관하거나 SQLite의 백업 API를 사용하세요. 백업에도 사진 보관 정책을 적용해야 합니다. `data/`, `.env`, `.venv/`는 Git에서 제외됩니다.

## 검증

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check static/app.js
```

실제 API 경로로 회원·운영자 권한, CSRF, 업로드/교체, 날짜 경계, 벌금, 납부, 휴식, 보관 만료, 업로드 즉시 승인과 사후 반려를 검증합니다.
